# Джарвис — приложение

Локальный голосовой и текстовый помощник для Windows по документу
«Джарвис — архитектура и дизайн» (v1.0). Всё «мозговое» работает на устройстве.

Папка самодостаточная: остальной репозиторий она не трогает.

## Быстрый старт

Нужен Python 3.10+. Ядро работает **без внешних пакетов**.

```bat
cd jarvis-app
python -m jarvis            :: окно приложения (или вкладка браузера)
python -m jarvis --dry-run  :: тестовый режим: действия только пишутся в журнал
```

На Windows можно запустить двойным щелчком по `run_jarvis.bat`.

### Голос через API — без установки на каждое устройство

Откройте ⚙ → «Распознавание речи» → «Через API» и вставьте ключ Groq.
Это **бесплатно**: ключ выдаётся на console.groq.com → API Keys по email,
без банковской карты. Модель — `whisper-large-v3-turbo`; бесплатный лимит
2000 запросов и 8 часов аудио в сутки — для голосовых команд с запасом.

Полностью бесплатный и офлайн вариант — локальный Whisper (`faster-whisper`, ниже).

Ключ хранится в Связке ключей macOS или в хранилище учётных данных Windows,
**в коде и в базе его нет** — не добавляйте ключ в репозиторий. В этом режиме
аудио (и только оно, после нажатия микрофона) уходит в облако; это осознанный
отход от принципа «всё локально», статус в окне показывает «Голос через облако».
Режим «Авто» использует API, если ключ сохранён, иначе локальный Whisper.

Дополнительные компоненты (всё локальное, ставится по желанию):

```bat
pip install -r requirements-optional.txt
```

| Пакет | Зачем |
|---|---|
| `pywebview` | отдельное окно вместо вкладки браузера |
| `faster-whisper` | локальное распознавание речи (если не нужен API) |
| `pyttsx3` | озвучка ответов офлайн (SAPI5) |
| `keyring` | хранение токенов коннекторов в Диспетчере учётных данных Windows |

Локальная LLM для нестандартных фраз: [Ollama](https://ollama.com) с моделью
из профиля (`ollama pull qwen2.5:7b-instruct` для Standard). Без неё работает
роутер правил, и Джарвис честно отвечает «не понял» на нестандартные фразы.

## Что умеет (MVP)

| Фраза | Что произойдёт |
|---|---|
| «Открой Телеграм и сверни остальные окна» | два шага, оба в журнале; окна можно вернуть кнопкой «Отменить» |
| «Открой ютуб» / «найди погоду в Москве» | откроет сайт или поиск в браузере |
| «Сверни все окна кроме хрома» | свернёт всё, кроме Chrome |
| «Закрой хром» | **спросит подтверждение** — риск потери данных |
| «Добавь задачу подготовить отчёт в 14:00» | задача в шторке «День» и точка на кольце |
| «Напомни завтра в 9 утра позвонить маме» | задача на завтра |
| «Отметь подготовить отчёт» | задача выполнена |
| «Что у меня на сегодня» / «итоги дня» | план и вечерний итог |
| «Отмени» | откатит последнее обратимое действие |
| «Стоп» / «продолжай» | аварийная остановка (kill-switch) |

Клавиши: **Пробел** (удерживать) — говорить, **Ctrl+D** — шторка «День»,
**Esc** — отмена/закрыть.

## Как устроено

```
jarvis-app/
├─ jarvis/
│  ├─ core/        оркестратор, роутер правил, нормализация и словарь, системные команды
│  ├─ security/    уровни риска, подтверждения, белый список программ, kill-switch
│  ├─ voice/       stt.py (локальный Whisper), stt_api.py (Whisper по API), tts.py, echo_guard.py
│  ├─ llm/         клиент Ollama, вывод по JSON-схеме, промпты
│  ├─ resources/   профили Lite / Standard / Pro, менеджер моделей
│  ├─ skills/
│  │  ├─ desktop/  программы, окна (WinAPI через ctypes; macOS — для разработки), ссылки
│  │  ├─ day/      задачи, план на день, вечерний итог
│  │  └─ messages/ сводка «только чтение» (заготовка этапа 6)
│  ├─ storage/     SQLite: tasks, events (журнал), settings, secrets (только ссылки)
│  ├─ gateway/     шлюз для телефона (заготовка этапа 7)
│  ├─ ui/web/      «Орбита» + кольцо дня, шторка «День», состояния окна
│  └─ server.py    локальный API ядра на 127.0.0.1
└─ tests/          python -m unittest -v
```

**Жизненный цикл команды** (`core/orchestrator.py`): ввод → нормализация →
роутер правил → LLM (если не узнали) → план → проверка политики →
подтверждение (если риск) → выполнение навыком → запись в журнал → ответ.

**Безопасность**
- Каждое действие проходит `security/policy.py`. `HIGH` (закрыть программу)
  выполняется только после «Подтвердить»; программа не из белого списка тоже
  спрашивает разрешения.
- Команды из текста сообщений (`source="message"`) и с телефона всегда требуют
  подтверждения: данные ≠ инструкции. Сводка сообщений идёт отдельным вызовом
  LLM без доступа к инструментам.
- LLM не может вызвать служебные инструменты (откат, system).
- API слушает только `127.0.0.1`, проверяет `Host` и требует токен сессии,
  поэтому сторонняя веб-страница не может отправить команду.
- Журнал без паролей; кнопка «Очистить данные» в настройках.

**Новый навык** — подпакет в `jarvis/skills/` с переменной `SKILL = Skill(...)`;
ядро подхватывает его автоматически, правка ядра не нужна.

Данные лежат в `%LOCALAPPDATA%\Jarvis\jarvis.db` (на macOS и Linux — `~/.jarvis`);
путь переопределяется переменной `JARVIS_DATA_DIR`.

## Отличия от документа и что дальше

- **Интерфейс:** выбран путь веб-интерфейса (ближе к Tauri), окно через `pywebview`.
  Связь UI ↔ ядро — HTTP JSON на localhost, а не WebSocket: для MVP хватает,
  а WebSocket понадобится для живой расшифровки и шлюза телефона.
- **Голос:** push-to-talk сделан, распознавание срабатывает после отпускания
  клавиши (живая расшифровка ещё не готова). Wake word и VAD-воркер пока не сделаны.
- **Процессы:** STT и LLM работают в отдельных процессах только в части LLM (Ollama).
  Голосовой воркер пока внутри ядра.
- **Не сделано:** browser bridge для вкладок (открытие URL работает и без него),
  коннекторы сообщений (этап 6), шлюз телефона (этап 7), повторяющиеся задачи
  (поле `repeat_rule` в схеме уже есть).
