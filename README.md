# J.A.R.V.I.S. — локальный голосовой ассистент

Голосовой ассистент на русском для Windows. Распознавание речи, нейросеть, голос и все данные работают на вашем компьютере. В интернет приложение ходит только по явной просьбе: погода, справка, «найди в сети», почта, сайт магазина.

Что умеет:
- отвечать на любые темы локальной нейросетью Qwen;
- выполнять быстрые команды без нейросети: время, таймеры, счёт, заметки;
- помнить факты о вас;
- вести план дня (кольцо суток вокруг реактора и шторка «День»);
- открывать любые установленные программы и управлять окнами;
- собирать заказ продуктов голосом и разбирать почту;
- искать ответы по вашим документам.

Действие, которое отправляет, удаляет или меняет данные снаружи, Джарвис выполняет только после вашего «да». Каждое действие записывается в журнал.

## Требования к железу

Профиль подбирается автоматически при первом запуске, поменять можно в настройках.

| Профиль | Железо | Whisper | Нейросеть | Ответ на быструю команду / вопрос |
|---|---|---|---|---|
| Лёгкий | без видеокарты, 8 ГБ ОЗУ | base | qwen2.5:1.5b | ~2 с / ~4 с |
| Стандартный | видеокарта NVIDIA от 6 ГБ | small | qwen2.5:7b | **~0,9 с / ~1,6 с** (замер на RTX 3060 Ti) |
| Максимальный | видеокарта от 10 ГБ | medium | qwen2.5:7b | ~1 с / ~1,8 с |

Время ответа считается от конца вашей фразы до начала голоса. Место на диске: около 6 ГБ под модели. Ни подписок, ни ключей не нужно.

## Установка (из исходников)

Нужно установить:
- [Ollama](https://ollama.com);
- Python 3.11+ и [uv](https://docs.astral.sh/uv/);
- Node.js 20+.

```powershell
# 1. Ядро (Python)
cd core
uv sync --extra cuda          # --extra cuda — Whisper на видеокарте NVIDIA; без неё уберите
uv sync --extra browser       # только если нужна автосборка корзины (этап 2 заказов)

# 2. Интерфейс
cd ..\app
npm install
npm run build

# 3. Оболочка
cd ..\shell
npm install
node node_modules\electron\install.js   # если npm не скачал Electron сам
```

Запуск: двойной клик по **`Запустить Джарвис.cmd`** или по ярлыку «Джарвис» на рабочем столе.

При первом входе откроется мастер:
1. Проверка микрофона.
2. Проверка Ollama и скачивание моделей кнопкой «Скачать». Это единственное место, где ядро ходит в сеть без вопроса в чате.
3. Выбор голоса.
4. Как к вам обращаться.

Данные лежат в `%APPDATA%\Jarvis`, а при запуске через `.cmd` — в папке `.devhome` рядом с проектом:
- база `jarvis.db`;
- модели `models\`;
- журнал ядра `core.log`.

Пароли почты хранятся в диспетчере учётных данных Windows (DPAPI), в базе их нет.

> Если запускаете Electron из терминала VS Code, сначала выполните `Remove-Item Env:ELECTRON_RUN_AS_NODE`. VS Code сам работает на Electron и выставляет эту переменную, из-за чего Electron стартует как обычный Node.

## Как пользоваться

| Действие | Как |
|---|---|
| Слушать / не слушать | пробел, клик по реактору, глобальная горячая клавиша (по умолчанию Ctrl+Alt+J) |
| Тишина и отмена | Esc, кнопка «Стоп», слово «стоп» |
| Ввод с клавиатуры | «/» |
| Шторка «День» | Ctrl+D |

Есть три режима слуха:
- **по обращению** — фраза начинается с «Джарвис»;
- **постоянно** — «Джарвис, слушай постоянно»;
- **по кнопке** — слушает только по кнопке или горячей клавише.

После ответа Джарвис 12 секунд слушает без обращения, чтобы можно было продолжить разговор.

Полный список команд выдаёт «что ты умеешь».

## Архитектура

```
app/      интерфейс: Vite + TypeScript без фреймворков; HUD-реактор на canvas + кольцо дня
shell/    оболочка Electron: запускает ядро и Ollama, трей, горячая клавиша, автозапуск, уведомления
core/     ядро на Python: FastAPI + WebSocket
  jarvis/session.py     оркестратор: реплика → правила → LLM → политика → подтверждение → навык → журнал → голос
  jarvis/intents/       быстрые команды (INTENTS, порядок важен), роутер
  jarvis/llm/           клиент Ollama, сборка контекста, JSON {say, action, args, confirm}, системный промпт
  jarvis/voice/         VAD (Silero), STT (faster-whisper), TTS (Piper / Silero), озвучка по предложениям
  jarvis/security/      уровни риска, подтверждения, «сеть только по просьбе», аварийная остановка
  jarvis/skills/        навыки: system, timers, notes, info, memory, day, desktop, order(+recipes), mail, knowledge
  jarvis/auth.py        профили, argon2id, экспорт и импорт (scrypt + AES-GCM), удаление всех данных
scripts/  иконка, оценка модели (eval_llm.py + 50 фраз), дообучение LoRA, Modelfile
tests/    pytest для ядра (409 тестов)
```

Конвейер голоса устроен так:
1. Микрофон в окне (Chromium с эхоподавлением) отдаёт PCM16 16 кГц в ядро по WebSocket.
2. Silero VAD режет поток на фразы, Whisper (CUDA) распознаёт, строка расшифровки видна крупно в окне.
3. Роутер отвечает сам или отдаёт фразу LLM. Поле `say` вытаскивается из потока токенов на лету.
4. Piper синтезирует ответ по предложениям, и голос начинается до конца генерации.
5. WAV уходит в окно и играет там же. Поэтому эхоподавитель вычитает голос Джарвиса из микрофона.
6. Пока Джарвис говорит, фразы принимаются только как перебивание («стоп», «Джарвис …»).

**Почему слово обращения распознаётся через Whisper, а не openWakeWord.** Готовой русской модели «Джарвис» у openWakeWord нет: есть только английская «hey jarvis», а своя требует обучения на тысячах записей. Whisper и так распознаёт каждую фразу, найденную VAD. На видеокарте это 0,2 с, а проверка имени в тексте бесплатна и понимает падежи и искажения («Джарви», «Жарвис»). Цена решения — видеокарта работает на каждой фразе в комнате. Поэтому есть режим «по кнопке». Если понадобится экономия, на место проверки в `session.handle_utterance` встаёт openWakeWord со своей моделью.

## Безопасность и приватность

Уровни риска инструментов:

| Уровень | Что значит | Подтверждение |
|---|---|---|
| `read` | только читает | нет |
| `local` | меняет локальные данные (заметки, задачи) | нет, но пишется в журнал |
| `open` | открывает программу или сайт | нет, но пишется в журнал |
| `external` | меняет данные снаружи (почта, корзина магазина, закрытие окна) | карточка или голосовое «да» |
| `danger` | необратимо (удалить письма) | всегда, отдельно от плана, отключить нельзя |

Правила, которые соблюдаются везде:
- **Сеть только по просьбе.** Сетевой инструмент работает, только если в вашей фразе есть явная просьба («погода», «найди в сети»). Модель не может сама решить сходить в интернет.
- **Чужие данные — не команды.** Письма, страницы и документы попадают в промпт в блоке `<данные>`, а ход помечается недоверенным: любое действие после этого требует подтверждения. Пересказ письма делается вызовом LLM без инструментов, и его текст никогда не разбирается как команда. Это проверяется тестами.
- **Белый список.** В настройках можно отключить любой инструмент.
- **Защита API.** Ядро слушает только 127.0.0.1, проверяет Host и требует случайный секрет оболочки в каждом запросе. Чужая страница в браузере до него не дотянется.

## Как добавить команду (интент)

1. Напишите обработчик в навыке, например `core/jarvis/skills/info.py`:
   ```python
   def moon(ctx, m, text):
       return "Луна сегодня растущая, сэр."     # или Reply(say=..., log=...)
   ```
2. Добавьте одну строку в `core/jarvis/intents/rules.py`, **выше** широких шаблонов (`open`, `search`, `timer`, `note-add`):
   ```python
   intent("moon", r"(какая|фаза) луна", info.moon),
   ```
   Текст на входе уже нормализован: нижний регистр, `ё → е`. Если в шаблоне нужны цифры вместо числительных, добавьте `nums=True`.
3. Добавьте строку в `HELP_LINES` (`skills/system.py`) и минимум пять фраз в `tests/core/test_intents.py`.

## Как добавить инструмент (действие)

Действие с внешним миром оформляется как инструмент, а не прямо в интенте. Тогда оно автоматически проходит политику, подтверждение и журнал, и его может вызывать LLM.

```python
class LightArgs(BaseModel):
    room: str = Field(description="комната")

@tool("home.light_off", skill="home", title="Выключить свет", risk=Risk.EXTERNAL, args=LightArgs,
      description="выключить свет в комнате", summary=lambda a: f"Выключить свет: {a.room}")
async def t_light_off(ctx: Ctx, a: LightArgs) -> ToolResult:
    ...
    return ToolResult(say="Свет выключен, сэр.")
```

Из интента инструмент вызывается так: `await ctx.call("home.light_off", {"room": "кухня"})`. Новый модуль навыка подключите в `core/jarvis/skills/__init__.py`. Если инструмент ходит в сеть, укажите `network=True` и `explicit_re`.

## Как сменить модель

- **Другая модель Ollama:** скачайте её (`ollama pull qwen2.5:14b`) или нажмите «Скачать» в мастере, затем выберите в **Настройки → Модели → Нейросеть**.
- **Whisper:** base, small или medium — в тех же настройках или через профиль железа.
- **Голос:** Piper (Денис, Дмитрий, Ирина, Руслан) — скачивается в мастере. Silero ставится вместе с `torch`, потом выбирается движок «Silero».
- **Характер:** системный промпт редактируется в **Настройки → Характер**. Файл по умолчанию — `core/jarvis/llm/prompts/system_ru.md`.

После смены модели прогоните оценку, она займёт около минуты:

```powershell
core\.venv\Scripts\python scripts\eval_llm.py --model qwen2.5:7b
```

50 фраз проверяют:
- свободный диалог;
- честность («не знаю, найди в сети»);
- выбор инструмента;
- длину ответа для голоса;
- защиту от команд внутри цитат.

Текущий результат qwen2.5:7b — **49/50**, медиана ответа 1,4 с.

## Дообучение (LoRA, необязательно)

1. **Соберите данные.** Включите **Настройки → Приватность → «Собирать мои диалоги для дообучения»** (по умолчанию выключено, данные остаются локально). Наберите хотя бы 200–300 диалогов и нажмите «Выгрузить JSONL».
2. **Поставьте зависимости:** `cd core; uv sync --extra finetune`. Это около 5 ГБ; для 8 ГБ видеопамяти добавьте `bitsandbytes`.
3. **Обучите:**
   ```powershell
   core\.venv\Scripts\python scripts\finetune_lora.py --data jarvis-dataset.jsonl --base Qwen/Qwen2.5-7B-Instruct --merge
   ```
4. **Конвертируйте в GGUF** через [llama.cpp](https://github.com/ggml-org/llama.cpp):
   ```
   python convert_hf_to_gguf.py lora-out/merged --outfile lora-out/jarvis-f16.gguf
   llama-quantize lora-out/jarvis-f16.gguf lora-out/jarvis-q4_K_M.gguf q4_K_M
   ```
5. **Подключите к Ollama:**
   ```
   ollama create jarvis-lora -f scripts/Modelfile
   ```
   Затем выберите `jarvis-lora` в настройках.
6. **Сравните «до / после»:**
   ```
   core\.venv\Scripts\python scripts\eval_llm.py --model jarvis-lora --compare scripts\report-qwen2.5_7b.json
   ```
   Если стало хуже, вернитесь к базовой модели. На маленьком датасете так бывает часто.

## Тесты

```powershell
core\.venv\Scripts\python -m pytest            # из корня проекта: 409 тестов
cd app; npx tsc --noEmit                       # проверка типов интерфейса
core\.venv\Scripts\python -m jarvis.skills.recipes selftest   # рецепты магазинов (откроет браузер)
```

Покрыто тестами:
- интенты: по 5+ фраз на каждый, с числительными;
- фразы, которые должны уйти в LLM;
- парсер заказа и каталог магазинов;
- разбор времени задач;
- калькулятор без `eval`;
- весь конвейер реплики с поддельной LLM: повтор невалидного JSON, сеть без просьбы запрещена, `external` и `danger` требуют подтверждения, «стоп» обрывает ожидание, недоверенный контекст, сценарий корзины, память;
- поиск программ.

## Известные ограничения

- **Рецепты магазинов.** Самотест проходит только ВкусВилл. Самокат, Пятёрочка и Перекрёсток требуют правки селекторов после входа в аккаунт. Без рецепта Джарвис открывает сайт магазина с поиском по каждой позиции (этап 1).
- **Почта** проверена на тестах, но не на реальном ящике.
- **Qwen 7B** иногда ошибается в фактах. Промпт велит признавать незнание, но проверять важное всё равно стоит.
- **Установщик** собирается командой `powershell -File scripts\build.ps1` и попадает в `dist\JARVIS Setup <версия>.exe` (около 190 МБ). Это лёгкая сборка без CUDA-библиотек: Whisper работает на процессоре (~1,5 с на фразу), нейросеть через Ollama по-прежнему использует видеокарту. Модели в установщик не входят, их скачивает мастер первого запуска. Установщик не подписан, поэтому Windows покажет «Неизвестный издатель».
- **Название J.A.R.V.I.S.** принадлежит Marvel/Disney. Для личного использования это неважно, для распространения его стоит сменить.
